# 小米蓝牙遥控器 2 Pro × 索尼电视：从开 ADB 到一键换键

Apple TV 那只遥控器"值两百块"不是玩笑——顺手、盲按、一只就能控全场。Android TV 体系里最接近它的，公认是小米这只蓝牙遥控器。问题是：**它属于小米生态的产物，而我家是索尼，而且索尼我一度认为把蓝牙白名单焊死了。**

这件事最后是通的。不是刷机，不是 root，是开一次 ADB，然后把一份提示词交给能跑命令的 AI。

这篇按 CleanYourTV 的路子写：**你只负责两件事（开 ADB、在电视上按确认），剩下的交给 AI。**

---

## 先说结论：那两堵墙，其实都不是墙

| 你以为的问题 | 真实情况 | 证据 |
|---|---|---|
| 小米遥控器只认小米电视 | 它走的是**标准 BLE HID（HOGP）**，只要电视是蓝牙 HID 主机就能用。真正绑死小米生态的只有语音键和几个专属键 | 配对后系统把它登记为标准输入设备，节点 `Sources=0x101`（键盘 + D-pad），按键报文是 HID 键盘页用法码 |
| 索尼锁了蓝牙白名单，第三方设备扫不到 | 锁住的不是协议栈，是**系统设置那个"添加设备"界面**——它按设备类型过滤。协议栈一直在正常扫描 | 界面列表全空的那两分钟，蓝牙日志里持续出现 `btif_get_device_type ... type 1`（经典蓝牙设备被扫到），界面就是不显示 |
| （还会撞上的第三堵墙）配对成功却完全没反应 | Android 9 把 `BluetoothHidHost.connect()` / `setPriority()` 塞进了**隐藏 API 黑名单**。方法在框架里躺着，但应用调用 `getMethod()` 直接抛 `NoSuchMethodException`，看起来像"被索尼删了" | 同一份代码里 `getConnectionState()` / `getConnectedDevices()` 能正常调用，只有这两个不行；解除限制后立刻 `0 → 1 → 2` 连通 |

所以"不兼容"和"白名单"这两个前提都是真的，但**结论不该是换电视或换遥控器**——两处都能在应用层绕过去，不需要 root，不需要拆机。

---

## 用法：三步

### 第 0 步：开 ADB（唯一必须你亲手做的一步）

AI 替不了，因为这一步要在没连上的电视上完成。

**索尼 BRAVIA（Android 9 / Google TV）：**

1. `设置 → 系统 → 关于`
2. 光标停在「版本」上，连按 OK **7 次**，出现"您已是开发者"
   - 部分新固件要求在「Android TV OS build」上连按 10 次
3. 返回 `设置 → 系统 → 开发者选项`，打开 **USB 调试**
   - 如果还有「网络调试 / ADB over network」，一并打开
4. 电视保持开机，**别让它待机**（待机可能把调试开关关掉）

> 找不到入口就搜「型号 + 开启 ADB」，比通用教程准。索尼的菜单名各代固件不一致，但"连点版本号"这个逻辑是通的。

开完之后电视上会等着一个「允许 USB 调试吗？」的弹窗——**那是下一步 AI 连接时才会出现的，现在先记住别拒绝。**

### 第 1 步：把提示词交给能真正执行命令的 AI

关键点：**要能跑 shell 的**（Claude Code、Codex、WorkBuddy 之类）。手机聊天框、网页版对话框只能把命令念给你听，连不上你家电视。

新建一个任务，把下面整段贴进去，把方括号里的信息填好。它会自己编译工具、扫描、配对、修键，需要你在电视上动手时会停下来提醒你。

### 第 2 步：你只需配合三件事

1. **在电视上点「允许」**——弹窗出现时确认，勾"始终允许"
2. **让遥控器进入配对模式**——等 AI 说"准备就绪"之后，再同时长按「主页键 + 菜单键」5 秒，直到指示灯快闪（若无效再试「主页键 + 返回键」）。**先把手机蓝牙关掉**，遥控器连着手机就不再广播了
3. **按两下键验收**——按 Home、按 TV 键，各试一次

### 第 3 步：验收清单

- [ ] 按 **Home** 键，回到桌面（原来完全没反应）
- [ ] 按 **TV** 键，左侧弹出「输入选择」列表，方向键能上下移动、OK 能确认
- [ ] 方向键、OK、返回、音量原生可用
- [ ] 电视重启后遥控器能自己连回来（不用重新配）

四项全过，这事就完了。

## 提示词（可直接复制）

```text
请在我家的索尼 Android TV 上完成一件事：接入一只「小米蓝牙遥控器 2 Pro」，
并修好它按了没反应的 Home 键和 TV 键。你没有 root，也不需要 root，
全部操作走局域网 ADB。

【设备信息】
电视：索尼 BRAVIA，Android 9（SDK 28）
电视 IP：[填你的电视局域网 IP，如 192.168.1.50]
电脑：macOS
遥控器：小米蓝牙遥控器 2 Pro，广播名一般含「小米蓝牙遥控器」，按名称关键字匹配即可
（实际广播名可能是「小米蓝牙语音遥控器」，工具做模糊匹配，**不需要 MAC 地址**）

【参考实现 · 先读再动手】
开源仓库：https://github.com/YOUR_GITHUB/openappletvremot
技能名 openappletvremot，仓库根目录就是技能目录。资产对应关系：
- SKILL.md          完整执行流程 §1~§6，按序走
- scripts/tv.sh     connect / prep / pair / hid / keys / map / enable
- assets/btpair     配对 + 解除隐藏 API 限制 + connect HID（Java 源码）
- assets/btremap    无障碍按键重映射（Java 源码）
- release/          预编译 APK；scripts/build_apk.sh 是无 Gradle 构建链
- references/pitfalls.md  13 条实测走不通的路，报错先查这里

【阶段一 · 接通 ADB】
1. 我已在电视上打开「USB 调试」。连接后电视会弹「允许 USB 调试吗」，我会确认。
2. 先 adb connect <IP>:5555，等到 devices 状态变成 device 再继续。
   授权有延迟，最多等 60 秒，不要连续重连把弹窗刷掉。
3. 读回机型、Android 版本、SDK 版本，确认是 Android TV 且 ≥ Android 8。
   不满足就停下告诉我原因，不要硬做。

【阶段二 · 配对遥控器】
1. 先查 dumpsys bluetooth_manager 的 Bonded devices，看是否已经配对过。
2. 不要依赖系统的「添加设备」界面：这个界面按设备类型过滤，第三方遥控器
   经常列表为空。它会误导你以为设备没在广播。
4. 直连配对需要应用层 createBond：写一个最小 APK（扫描 + 按名称匹配 + 配对），
   或使用现成工具（openappletvremot 仓库 `assets/btpair`）。编译环境用 Android SDK
   build-tools + javac + d8，不要装 Gradle。
5. 全程不需要 MAC 地址，也不要让我念 MAC 或从列表里挑一台：
   直接按设备名关键字「小米蓝牙遥控器」模糊匹配即可（能命中「小米蓝牙语音遥控器」）。
6. 顺序很重要：先把工具装好、无障碍服务启用、一切准备就绪，**再**让我长按
   遥控器【主页键 + 菜单键】5 秒进入配对模式。别在我按完之后还在编译。
7. 扫描要循环做（如 20 秒一轮、最多 8 轮），扫到即配对。我切配对模式可能比
   扫描慢半拍，只扫一轮就报"找不到"会白折腾。配上失败（含 0x05）的设备要
   自动跳过换下一台，不要死磕同一台。
8. 如果配对失败且日志出现 result: 0x05（Authentication Failure）并伴随
   pairingVariant 0 passkey，说明对方要求输入 6 位密码而设备没有数字键盘，
   这类设备配不上，直接告诉我换设备，不要反复重试。

【阶段三 · 打通 HID 通道】
1. 配对成功不等于能用。检查 HidHostService 的 mInputDevices 是否为空。
2. 为空的原因不是厂商封锁，是 Android 9 把 BluetoothHidHost.connect() 和
   setPriority() 放进了隐藏 API 黑名单，普通反射会抛 NoSuchMethodException。
   不要因此判断"方法不存在"或"被厂商删了"。
3. 解法：先用双重反射调用 VMRuntime.setHiddenApiExemptions("L") 解除限制，
   再 setPriority(dev, 100)，然后 connect(dev)。状态应为 0 → 1 → 2。
4. 三项验收缺一不可：
   - mInputDevices 里该设备显示 : 2（CONNECTED）
   - dumpsys input 里出现遥控器设备节点 /dev/input/eventN
   - getevent -lt 该节点，按方向键能看到 MSC_SCAN 0007004f / EV_KEY KEY_RIGHT
5. 如果遥控器自己解绑（BOND_STATE_NONE），重新配一次即可，不用换方案。

【阶段四 · 修 Home / TV 键】
1. 先解释原因再动手：这只遥控器的 Home 键发的不是 KEYCODE_HOME(3)，而是
   KEYCODE_MOVE_HOME(122)——文本框里"移到行首"用的键，电视上没有文本框，
   所以按了毫无反应。TV 键发 KEYCODE_GRAVE(68)，也是个没人接的空键。
2. 不要改 /system/usr/keylayout（只读分区，无 root 改不了），
   也不要试图注入按键（INJECT_EVENTS 是签名权限，拿不到）。
3. 正确路径：装一个无障碍服务做按键重映射。它只能做两件事——执行系统全局动作，
   或启动某个 Activity。别承诺它能"拦截 A 键发出 B 键"。
4. 映射参数写进 Settings.Secure，改完即时生效，不用重启、不用重装：
   Home(122) → 系统主页
   TV(68)   → 输入选择
5. 索尼的输入选择界面是 com.sony.dtv.tvx/com.sony.dtv.tvx.inputselect.InputSelectionActivity，
   直接 startActivity 会在一秒内自退，必须附带 KEY_EVENT extra，键码用
   KEYCODE_TV_INPUT(178)，flag 用 NEW_TASK | CLEAR_WHEN_TASK_RESET | NO_ANIMATION。
   这是它和自家遥控器按键广播一致的启动方式。

【阶段五 · 验证】
1. 让我按 Home 和 TV 键实测。判断界面有没有弹出要看截图 + 方向键高亮是否移动，
   不要看 mCurrentFocus——这类浮层不抢焦点，那个字段仍显示桌面，会误判成失败。
2. 不要用 input keyevent 自测映射：注入事件带 FLAG_INJECTED，不经过无障碍
   按键过滤器，测了也是白测。必须真按遥控器。

【约束】
1. 不要 adb root（量产机必然失败），不要改 /system，不要 pm uninstall 系统应用。
2. 不要启动 factory / fac menu / production 等工厂测试包。
3. 全程把每步的实际命令输出给我看，不要只说"已完成"。
4. 最后告诉我：电视上装了什么、改了哪些系统设置、怎么一键回滚、ADB 怎么关。

【可选 · 语音键】（默认跳过，我明确要求再做）
语音键和 TV 键同类：抓键码（实测是 KEYCODE_F5/135），写映射时动作用 s（ACTION_ASSIST），
真按遥控器测。风险：电视本体没有麦克风，可能只弹提示就退出；若界面起但无拾音，
改用手机 Google TV App 走 WiFi 送语音。不要为此改 /system、audio_policy 或装第三方语音助手。

需要我在电视上操作或确认时，先停下来告诉我该按什么、按几下。
现在开始。
```

## 过程：它是怎么被跑通的

给想知道原理的人。每一步都有实际输出作为依据，不是推测。

| 阶段 | 关键动作 | 观察到的结果 |
|---|---|---|
| 扫描 | 系统「添加设备」页开 2 分钟 | 界面始终空；蓝牙栈日志持续出现 `btif_get_device_type ... type 1`，还夹着 `discarding advertising packet`——UI 在丢包 |
| 配对 | `createBond()` 直连 MAC | `BOND_NONE → BONDING → BONDED`，1.2 秒完成，设备名"小米蓝牙语音遥控器"，`[LE]` 标记 |
| 撞墙 | 反射 `BluetoothHidHost.connect()` | `NoSuchMethodException: connect`，但同一代理的 `getConnectionState` / `getConnectedDevices` 正常 |
| 拆墙 | `VMRuntime.setHiddenApiExemptions("L")` | `setPriority(100) = true` → `getPriority = 100` → `connect() = true` |
| 连通 | 电视侧状态机 | `Connection state ...: 0->1->2`，`mInputDevices: <MAC> : 2` |
| 落地 | 系统输入设备 | 第 5 号设备 = 遥控器，`/dev/input/event4`，`vendor=0x2717`（小米），`Sources=0x101` |
| 验真 | `getevent -lt` | `MSC_SCAN 0007004f → KEY_RIGHT`、`0x70050 → KEY_LEFT`，DOWN/UP 完整，是标准 HID 键盘用法码 |
| 修键 | 无障碍按键过滤 | `code=122 KEYCODE_MOVE_HOME` → 映射后 `remap 122 -> global 2 ok=true`，按 Home 回到桌面 |
| 修键 | TV 键 → 输入选择 | `code=68 KEYCODE_GRAVE`，带 `KEY_EVENT(178)` 拉起后浮层常驻，方向键能把高亮从第一项移到第二项 |

两处值得记住的判断纠正：

- `Settings.Global.bluetooth_input_device_priority_<MAC>` **不是**旧版遗留的废键，它就是 Android 9 存 HID 优先级的地方，`setPriority(100)` 写的就是它，重启不丢，之后遥控器回到范围内会自动回连。
- 索尼**没有**在 HID 准入上做拦截。整个过程零 `Permission Denial`，唯一的拦路者是 Android 自己的隐藏 API 策略。

## 未验证的部分：语音键

**结论是"没验通"，不是"验不通"。**

已知事实：这台电视本体**没有麦克风**——`/proc/asound/cards` 为空、`audio_policy` 里 `Available input devices` 为空、`pm list features` 里只有 `android.hardware.audio.output`。索尼的语音链路是"遥控器麦克风采集 → 蓝牙回传 → 电视识别"，所以只把语音键映射成"唤起语音"，界面可能起来但电视没有拾音入口。

但按键本身和 Home / TV 是同一类问题：**键码能抓到，缺的是把它接到系统语音入口。** 处理方式完全照 TV 键：

1. `getevent -lt` 抓真实键码（实测语音键是 `KEYCODE_F5(135)`，属于没人接的空键）；
2. 写入映射时动作用 `s`（`ACTION_ASSIST`）：`135>s>`
3. 真按遥控器测，不要 `input keyevent` 自测（注入事件带 `FLAG_INJECTED`，不过无障碍过滤器）。

若界面起来却无声音输入，备用路是手机装 Google TV App 走 WiFi 把语音送过去（电视端这条通道是通的）。要一按就说话的稳定体验，原厂语音遥控器仍是唯一省事解。

## 安全与回滚

会留在电视上的东西：

- 两个小工具：一个负责配对/接 HID，一个负责按键重映射（源码公开，可自己编译）
- 两条系统设置：`Settings.Secure.btremap_map`（按键映射）、`Settings.Global.bluetooth_input_device_priority_<MAC>`（HID 优先级）
- 一条蓝牙配对记录

撤销：

```bash
# 停用按键映射（立刻恢复原始键位行为）
adb shell settings put secure enabled_accessibility_services ''

# 卸载工具（配对关系保留，遥控器仍可用，只是键位回到原样）
adb shell pm uninstall <重映射工具包名>

# 关掉调试口子（强烈建议做完就关）
# 电视：设置 → 开发者选项 → 撤销 USB 调试授权
```

ADB 的 5555 端口是明文传输，**长期敞开不是好习惯**。全部做完就关。

## 附：不用 AI 的手动路线

如果你更想自己敲：

```bash
# 1. 连电视
adb connect <IP>:5555 && adb devices

# 2. 装配对工具（源码见 openappletvremot 仓库 assets/btpair）
adb install -r btpair.apk

# 3. 准备就绪后，长按遥控器【主页 + 菜单】5 秒至指示灯快闪，再执行：
#    按名称关键字自动匹配并配对，配对成功会自动接 HID（不需要 MAC）
adb shell am start -n <包名>/.MainActivity --ez scan true --ez autobond true -e name 小米蓝牙遥控器
adb logcat -d | grep BTPair | grep -E 'TARGET_MATCH|BOND |RESULT=SUCCESS'

# 4. 确认 HID 通了
adb shell dumpsys bluetooth_manager | grep -A3 'Profile: HidHostService'
adb shell dumpsys input | grep -E '^ +[0-9]+: '

# 5. 装重映射工具、写映射、启用
adb install -r btremap.apk
adb shell settings put secure btremap_map '122>g>2;68>k>com.sony.dtv.tvx/com.sony.dtv.tvx.inputselect.InputSelectionActivity:178'
adb shell settings put secure enabled_accessibility_services <包名>/<包名>.RemapService
adb shell settings put secure accessibility_enabled 1
```

映射串格式：`源键码 > 动作 > 参数`，多条用 `;` 分隔。动作 `g`=系统动作（1 返回 / 2 主页 / 3 最近 / 4 通知），`a`=启动界面，`k`=启动界面并附带按键，`s`=语音助手意图。

## 已知不确定

- **2 Pro 的配对键组合**：首选**主页 + 菜单 同按 5 秒**；不同代次也可能用主页+返回、语音+返回、确认+主页，以指示灯快闪为准。配对模式没进去，扫多久都是白扫（工具会循环扫 8 轮，不是扫一次就放弃）。
- **索尼固件的菜单名**：`系统` / `设备偏好设置` / `关于` 这三级的叫法各代不同，找不到就搜型号。
- **待机会关调试**：部分机型从待机唤醒后会关掉 ADB，操作期间别让电视睡。
